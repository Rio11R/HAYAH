# HAYAH — عقد الربط المقترح مع واجهة نور

**الحالة: PROPOSED — غير معتمد وغير منفذ كواجهة تطبيق.** هذه مسودة DEC-06، مستندة إلى MPS v0.3 (الأقسام 5–8 و14) والبيانات الأصلية v0.3. لا تثبت لغة التطبيق أو HTTP أو إطار عمل؛ أسماء العمليات أدناه للتنسيق فقط. لا تُضاف الحقول المقترحة للطلبات والنتائج إلى ملف JSON الأصلي.

الاعتماد الفني: عبدالإله + نور + الريان. أي تعديل لعقد البيانات أو المحاكاة يحتاج موافقة أحمد، وفق القسم 9 من MPS. أحمد مرشد ومعتمد قرارات؛ فريق التنفيذ خمسة: عبدالإله، نور، الريان، عمار، تاج.

## قواعد مشتركة مقترحة

- المصدر هو `data/hayah_master_data_v0_3.json` كما هو؛ لا تطبيع لقيم `status` أو تحويل للقيم الفارغة. البيانات اصطناعية بالكامل.
- المجموعات الحالية: `patients`, `ambulances`, `departments`, `staff`, `equipment`, `beds`؛ مفاتيحها على الترتيب `patient_id`, `ambulance_id`, `department_id`, `staff_id`, `equipment_id`, `bed_id`.
- المستشفى موجود تحت `meta.hospital` بمعرف `HOSP-01`، وليس مجموعة مستقلة أو توأمًا مجمعًا محسوبًا.
- القيم `""` في `ambulance_id` و`next_department_id` تعني عدم وجود ارتباط؛ لا تُستبدل بـ `null`. القيمة `Ambulance` في `current_department_id` علامة موقع، وليست معرف قسم مفقودًا. `predicted_path` يحتوي معرفات أقسام.
- المطابقة حساسة لحالة الأحرف: `En_route` للمريض و`en_route` للإسعاف، و`Available` للطاقم مقابل `available` للمعدات/الأسرّة. تُعرض القيم الحالية دون تعديل.
- مقترح الطلب/النتيجة: نجاح يعيد البيانات المطلوبة مع مرجع اللقطة؛ فشل يعيد رمزًا ورسالة وتفاصيل الحقل المعني، دون نتيجة جزئية أو تغيير للحالة. أسماء الغلاف ومرجع اللقطة تحتاج اعتمادًا؛ ليست حقولًا قائمة في JSON.
- مقترح الأخطاء: `NOT_FOUND` لمعرف غير موجود، `INVALID_INPUT` لنوع أو قيمة غير صالحة، `INVALID_REFERENCE` لارتباط مكسور، `STALE_STATE` لتحديث مبني على نسخة أقدم، و`UNAPPROVED_RULE` لقاعدة لم تعتمد. هذه رموز عقد مقترحة، وليست سلوك مكتبة Python الحالية.
- إلى حين اعتماد إدارة الحالة المشتركة: لا يوجد مخزن تطبيق متغير ولا أحداث تحديث منفذة. المقترح لاحقًا مصدر حالة واحد في ذاكرة العرض، مع بقاء ملف المصدر ثابتًا ونسخ مستقلة للمحاكاة. كيفية تعيين إصدار اللقطة وتسجيل الأحداث وإعادة العرض معلقة في DEC-05/06.

## العمليات المطلوبة

| العملية المنطقية المقترحة | المدخلات المطلوبة | المخرجات المطلوبة ومعيار القبول | ما يحتاج اعتمادًا قبل التنفيذ |
|---|---|---|---|
| `loadDemoData` | مصدر JSON الاصطناعي المتفق عليه | لقطة البيانات كما هي، أعداد المجموعات، قائمة الحالات التفاعلية من `meta.interactive_patient_ids`، وأخطاء/تحذيرات الفحص منفصلة. تحميل متسق لجميع مكونات الواجهة؛ لا كتابة إلى المصدر | طريقة التحميل وربطها بالواجهة، سياسة منع العرض عند الخطأ، شكل غلاف النتيجة |
| `getTwinState` | اسم المجموعة ومعرف السجل؛ وللمستشفى قراءة `meta.hospital` | السجل الأصلي بكامل حقوله دون إثراء أو تطبيع؛ معرف غير موجود ينتج `NOT_FOUND`. العلاقات تُقرأ من حقولها الحالية؛ موارد القسم من `department_id` | أسماء المجموعات في الواجهة، شكل نتائج المستشفى المجمع لاحقًا، سياسة عرض العلاقات |
| `updateAmbulanceETA` | معرف إسعاف، قيمة `eta_minutes` بالدقائق، مرجع نسخة الحالة التي بني عليها التعديل | نسخة عرض جديدة تتضمن الإسعاف المعدل والتوائم/المؤشرات المتأثرة وسبب التغيير وفق قاعدة معتمدة. مثال قبول لاحق: `AMB-101` من 7 إلى 4 دقائق مع تطابق النتيجة مع مثال يدوي معتمد؛ المصدر لا يتغير | أعداد صحيحة أم كسور، حدود القيم، نافذة التنبؤ، انتقال الوصول عند الصفر، انتشار الحدث، معالجة التعارض. دون القاعدة لا تُختلق أعداد قادمة |
| `updateTwinState` | نوع الكيان، معرفه، تعديل محدود لحقول معتمدة، مرجع نسخة الحالة | تحديث حقول مسموحة فقط دون فقد باقي السجل، تحقق من المراجع والانتقالات، وبيان التوائم المتأثرة. الخطأ يرفض العملية كاملة؛ لا تغيير للمعرفات | قائمة الحقول القابلة للتعديل لكل كيان، الانتقالات المسموحة، ملكية التحديث، قواعد الترابط والتعارض |
| `calculateOperationalPressure` | لقطة متسقة للأقسام والموارد والمرضى والإسعاف، ومرجع مجموعة قواعد/أفق زمني معتمدين | مؤشرات لكل قسم مع المدخلات المستخدمة، شرح الحساب، الافتراضات والحدود ومرجع اللقطة/القاعدة. النتيجة قابلة لإعادة الحساب يدويًا؛ لا تُظهر انتظارًا أو دقة متوقعة دون أساس معتمد | صيغة التنبؤ الديناميكي، السعة الفعالة، أثر ETA والموارد، وحدات النتائج. قاعدة فحص اللقطة في JSON ليست اعتمادًا لطريقة تنبؤ مستقبلية |
| `runScenario` | نسخة واحدة ثابتة للحالة الابتدائية، السيناريو المطلوب، افتراضات وتدخلات معتمدة | نتيجة مستقلة واحدة للسيناريو المطلوب، موسومة «نتيجة محاكاة» مع مرجع البداية والافتراضات. تُستدعى العملية ثلاث مرات من نفس البداية: دون تدخل؛ إعادة توزيع موارد؛ إعادة تنظيم تدفق حالات مناسبة. بعد اكتمال النتائج تُجهّز المقارنة والتوصية المفسّرة بخطوة تنسيق مقترحة لم تُنفذ؛ لا تعديل للأصل | DEC-04، حدود التدخلات، أوقات الخدمة، أفق المحاكاة، المقاييس وقاعدة ترتيب التوصية. لا أرقام انتظار أو تحسن مختلقة |
| `recordHumanDecision` | مرجع التوصية/السيناريو المعروض ونسخة بدايته، اختيار صريح قبول أو رفض | سجل قرار تجريبي مرتبط بالنتيجة التي راجعها الإنسان، ثم الحالة المعروضة المناسبة. الرفض يبقي الحالة دون تطبيق التدخل. القبول المسجل وحده يسمح بتطبيق التدخل المعتمد على حالة العرض/المحاكاة؛ لا مستشفى حقيقي ولا تعديل لملف المصدر | شكل سجل القرار، كيفية تسجيل الزمن والفاعل التجريبي دون بيانات شخصية، سياسة القرارات المكررة والنتائج القديمة، حفظه داخل جلسة العرض أو خارجها |

نتائج المقارنة تشمل الضغط واستغلال الموارد، ويمكن أن تشمل زمن الانتظار/الرحلة فقط إذا اعتمد الفريق مدخلاتهما وقواعدهما. لا يُعاد استخدام نتائج سيناريو كمدخل للآخر. نطاق السيناريوهات الثلاثة معتمد، لكن محركها وصيغها ليست معتمدة بعد.

## ما هو متاح في Phase 1

أدوات `hayah_inspect.py` هي أدوات فحص محلية للقراءة فقط، وليست تنفيذًا للأسماء المقترحة أعلاه أو اختيارًا لـ Python كخادم التطبيق. تستخدم نور البيانات الأصلية وهذه المسودة للمراجعة؛ لا يُعلن أن التكامل التفاعلي مكتمل.

| أداة الفحص المحلية | الغرض |
|---|---|
| `DatasetInspector.load(path)` و`snapshot()` | قراءة لقطة JSON وفحصها دون تغيير المصدر |
| `records(section)` و`get(section, id)` | قراءة المجموعات والسجلات الحالية |
| `interactive_patients()` | استرجاع الثمانية المحددين في metadata وبترتيبهم |
| `resources(dept_id)` | فحص الطاقم والمعدات والأسرّة المرتبطة بالقسم |
| `operational_indicators(dept_id=None)` | قراءة مؤشرات اللقطة القائمة دون تنبؤ جديد |
| `relationship_errors()` | فحص المراجع الحالية دون تحديث أي سجل |

مثال سجل موجود كما هو، يصلح مرجعًا لمراجعة القراءة:

```json
{"ambulance_id":"AMB-101","eta_minutes":7,"status":"en_route","patient_id":"PAT-001"}
```

الحالات التفاعلية الحالية: `PAT-001` إلى `PAT-008` كما في `meta.interactive_patient_ids`، وليست سجلات إضافية فوق الخمسين.

## بوابة اعتماد التكامل

يحدد عبدالإله الحقول والعلاقات مع الريان، وتراجع نور المدخلات/المخرجات، ثم يوثق الفريق ما تم اعتماده في DEC-06. يرفق لكل عملية تحديث مثال صحيح وآخر مرفوض. لا يبدأ تنفيذ التحديث والتنبؤ والمحاكاة قبل تثبيت القواعد المعنية، ولا تعد هذه المسودة موافقة على Phase 2.
